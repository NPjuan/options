# 美股期权模拟交易终端

接入 CBOE 官方延迟报价的期权模拟交易器。真实期权链、真实希腊字母、完整下单与风险管理。

线上体验：https://options-weld.vercel.app

零第三方依赖 —— 仅用 Node 内置模块，前端手写 Canvas 图表，无构建步骤。

## 快速开始

```bash
git clone git@github.com:NPjuan/options.git
cd options
npm run dev        # 等价于 node server.js
# 浏览器打开 http://localhost:8848
```

需要 Node 18+。如需换端口：`PORT=9000 npm run dev`

## 运行测试

```bash
npm test           # 全部测试
npm run test:math      # 定价引擎（Hull 教科书基准、平价关系、希腊字母 vs 数值微分）
npm run test:account   # 账务（加权均价、反向换仓、现金守恒、到期结算）
npm run test:calendar  # 日历价差多到期日损益
npm run test:api       # 服务层（路由、gzip、4.5MB 响应体上限校验）
npm run test:ui        # 界面（需 playwright-core + 本机 Chrome，缺失则自动跳过）
```

前三个测试完全离线；`test:api` 会启动真实服务并请求 CBOE，验证大标的响应体积。

## 部署到 Vercel

```bash
npm i -g vercel
vercel          # 预览环境
vercel --prod   # 生产环境
```

或在 Vercel 网页端直接 Import 这个 GitHub 仓库，零配置、无构建步骤。

**不需要改端口。** Vercel 会注入 `PORT` 环境变量，`server.js` 直接读取；
本地缺省 8848。同一份 `server.js` 既是本地开发服务，也是线上入口，
静态文件与 `/api/*` 都由它处理，不存在两套代码路径。

唯一按环境区分的是监听地址：

| | 监听地址 | 原因 |
|---|---|---|
| 本地 | `127.0.0.1` | 不把服务暴露到局域网 |
| 线上 | `0.0.0.0` | 否则平台无法把流量转进容器 |

### 部署时踩过的坑

**必须 gzip。** 多数平台（含 Vercel）单次响应体上限 4.5MB，而 SPX
精简后的 JSON 实测 **5.5MB**，不压缩直接失败。gzip 后降到 1.2MB
（压缩比约 4.6x）安全通过。`test/api-test.js` 对此有专门断言 —— 否则
本地开发永远不会暴露这个问题。

**入口文件不能被忽略。** 平台把本项目识别为 Node 服务应用，会按
`package.json` 的 `main` 找入口。若移除 `main`、或在 `.vercelignore`
里排除了 `server.js`，就会报 `No entrypoint found`。
`main: "server.js"` 与 `start` 脚本都要保留。

**运行时读取的文件必须显式声明。** 这是本项目部署中最隐蔽的一个坑：
平台按 `require` 图做静态分析来决定打包哪些文件，而 `index.html`、
`style.css`、`js/*.js` 都是运行时用 `fs.readFile` 读的，
分析器看不到它们，于是不会进产物 —— 表现为 API 正常但**所有静态资源 404**。

解决办法是在 `vercel.json` 里用 `builds.config.includeFiles` 显式列出，
并用 `routes` 把全部请求指向 `server.js`：

```json
{
  "builds": [{
    "src": "server.js",
    "use": "@vercel/node",
    "config": { "includeFiles": ["index.html", "style.css", "js/**", "lib/**"] }
  }],
  "routes": [{ "src": "/(.*)", "dest": "/server.js" }]
}
```

同时 `server.js` 不再假设 `__dirname` 等于仓库根，而是逐候选目录探测
`index.html` 的真实位置（线上实测为 `/var/task`）。
`/api/health` 会返回 `root` 与 `staticOk` 两个字段，出问题时可一眼定位。

## 数据来源

CBOE 官方延迟报价接口（`cdn.cboe.com`），约 15 分钟延迟，含：

- 标的实时报价、日内高低、成交量、30 日隐含波动率
- 完整期权链：每个到期日 × 每个行权价的认购/认沽
- 买卖价与挂单量、成交量、未平仓量（OI）
- CBOE 自算的 IV、Delta、Gamma、Theta、Vega、Rho、理论价

该接口无 CORS 头，浏览器无法直连，因此由 `server.js` 代理并把原始
1.4~12MB 的响应压缩成约 160KB 的精简结构（内存缓存 20 秒）。

支持股票（AAPL、TSLA…）、ETF（SPY、QQQ…）与指数（SPX、VIX、NDX，自动加下划线前缀）。

## 功能

**期权链**
- 按到期日分组，认购/认沽并排，平值行高亮，价内行加深底色
- 可开关希腊字母列与成交量/持仓量列，可只看平值 ±N%
- 定价 IV 可选「市场 IV」或「自算 IV」（用中间价反解）

**下单**
- 点击买价/卖价单元格即选中合约
- 三种成交价模式：中间价（理想）、吃对手价（真实）、挂单价（乐观）
- 实时显示成交价、名义金额、佣金、保证金、总支出
- 内在价值/时间价值拆解、买卖价差占比、到期盈亏平衡点
- 单腿到期损益图
- 流动性差（价差 >15% 或 OI <10）会主动告警

**持仓与风险**
- 实时盯市：浮动盈亏、已实现盈亏、累计佣金
- 组合希腊字母汇总，并换算为「等效持股数」与占权益比例
- 组合到期损益图 + 当前理论曲线，支持时间推移与 IV 冲击滑块
- 9×5 情景压力矩阵（价格 ±15% × 未来 0~30 天）
- 资金曲线、胜率、盈亏比统计

**策略模板（12 种，一键建仓）**
单腿认购/认沽、牛市认购价差、熊市认沽价差、牛市认沽价差、跨式、宽跨式、
卖出宽跨式、铁鹰、蝶式、日历价差、认购比率价差。
建仓前可调张数、行权价间距与到期日，实时预览四腿明细、最大盈亏、盈亏平衡点。

**账户**
- 初始资金、佣金、最低佣金、滑点模式、无风险利率均可配置
- 持仓与流水存于 localStorage，刷新不丢
- 支持到期结算（价内按内在价值自动行权，价外作废）

## 定价引擎的几个关键实现

**1. 正态分布 CDF 用 Hart 双精度有理逼近（精度 ~1e-15）**
常见的 Abramowitz-Stegun 近似只有 1e-7，而期权 delta 就等于 N(d1)，
精度不足会直接污染整个风险面板。实测 A&S 会让 delta/vega/rho 出现
1e-5 量级偏差；换成 Hart 后与数值微分吻合到 1e-15。

**2. 估值时点对齐行情快照，而非本地"当前时间"**
CBOE 的希腊字母是按最近交易时点计算的。若用本地墙上时间算剩余期限，
周末或盘前会凭空少算 2~3 天 —— 实测导致 vega 偏低约 5%、反解 IV 偏高
约 1.4 个百分点。现改为以 `last_trade_time`（美东）为基准，
DTE 因此都是整数天。同时正确处理美东夏令时/冬令时切换。

**3. 定价用「市场隐含远期价」，而非直接用现价 + 反解股息率**

CBOE 返回的标的现价与期权报价常不是同一时刻的快照 —— 实测 NVDA 期权链
隐含的标的价比 `current_price` 低 0.53%，且这个偏离在**所有行权价上高度一致**
（各档反解出的远期价彼此偏差 < 0.05%），说明它来自快照错配而非噪声。

最初的做法是把这个缺口当成股息率反解，结果 21 天的 0.5% 缺口被年化放大成
**14.5% 的股息率**（NVDA 实际约 0.03%），TSLA 甚至出现 **−8.2%**。

现改为：由看跌看涨平价关系 `C − P = e^{−rT}(F − K)` 反解隐含远期价 F，
再折现得到「等效现价」`effSpot = F·e^{−rT}`，以零股息定价。这等价于
Black-76 远期定价，能自动吸收股息、借券成本与快照错配，且严格满足平价关系。

反解 F 时用**中位数**而非最小二乘 —— 个别宽价差合约会严重拖偏回归线；
同时优先采用买卖价差 <6% 的样本。损益图横轴仍显示真实价格，
通过 `spotScale` 系数把定价基准衔接过去。

**4. 与 CBOE 官方希腊字母的实测吻合度**

在 6 个标的（AAPL / NVDA / TSLA / MU / SPY / SPX）、908 个近月平值合约上对比：

| 指标 | 平均绝对误差 |
|---|---|
| 理论价 | $0.42 |
| Delta | 0.0053 |
| Vega | 0.038 |
| 反解 IV | 0.42 个百分点 |

残余差异来自 CBOE 使用美式二叉树（含提前行权与离散股息），
而本引擎是欧式 BS 闭式解。对模拟器而言精度充分。

**5. 平仓统计按 action 判定，而非按盈亏是否为零**

以中间价开仓后立刻平仓，已实现盈亏恰好为 0。若用 `realized !== 0` 筛选平仓单，
这类真实平仓会被整体漏掉（实测 8 笔平仓统计成 0 笔）。现改为按 `action`
字段判定，并把「平局」单独计数、不计入胜率分母。

**6. 多到期日组合的损益按「最近腿到期时刻」计算**

日历价差的两条腿到期日不同。若一律取内在价值，远月腿的剩余时间价值会被抹掉，
损益曲线退化成一条水平线 —— 实测日历价差的「最大盈利」与「最大亏损」
算出来完全相等（都是 −$195），明显错误。

现在 `payoffAtExpiry` 以最近到期的腿为观察时点，对尚未到期的腿按 BS 重新定价。
修复后日历价差呈现正确的帐篷形：行权价附近盈利最大，两侧递减，两个盈亏平衡点。
界面上这类组合的标签也相应改为「近月到期时最大盈利/亏损」。

**7. 识别并提示「中间价套利假象」**

多腿策略在中间价成交假设下，每条腿都白拿半个买卖价差，累加后可能凭空生出利润 ——
实测蝶式在中间价下显示「最大亏损 +$4」，即无风险套利，现实中不存在。
切到「吃对手价」后回归正常的 −$140 借记。

现在检测到「最大亏损 ≥ 0」且处于中间价模式时，会明确提示这是价差假象
并建议切换成交模式，而不是让用户误以为发现了免费午餐。

## 模拟器与实盘的差距（重要）

这是模拟器，以下简化会让结果比实盘乐观：

- **无冲击成本**：假设你的单子不影响价格，按报价全额瞬时成交。真实中
  大单会推动价格，流动性差的合约尤其明显。
- **买卖价差是最大偏差源**：默认「中间价」模式几乎不可能成交。想贴近
  真实请切到「吃对手价」，感受价差对高频进出的侵蚀。
- **保证金模型是简化的**：卖方按「权利金 + 20% 标的市值」估算，
  真实券商用 SPAN/组合保证金，规则更复杂也更严格。
- **数据延迟约 15 分钟**，且非交易时段为上一收盘快照。
- **不含提前行权、离散股息、除权调整、行权指派风险**。
- 美式期权按欧式定价，深度价内认沽会略有低估。

## 界面层架构

界面刻意保持零依赖 —— 没有 React/Vue，也没有构建步骤。这个选择成立的前提是
定价、账务、图表都在独立模块中且有测试覆盖，与界面实现无关：

| 层 | 行数 | 是否受界面框架影响 |
|---|---|---|
| `optionmath.js` + `account.js` + `lib/cboe.js` | 1225 | 否，纯逻辑 + 测试覆盖 |
| `charts.js` | 427 | 否，Canvas 命令式绘制 |
| `app.js` | ~1500 | 是，唯一的界面层 |

因此把力气花在解决界面层的真实痛点上，而不是整体重写。

### 按变化源刷新，而不是全量重画

界面由 8 个区块组成，各自的数据依赖并不相同。早先任何操作都调
`renderAll()` 重画全部区块，代价有两处：SPX 有 164 行 × 17 列外加 5 个
Canvas 图表，一次下单要全量重建；而重建 `innerHTML` 会让**表格滚动位置归零**，
下单后视图跳回顶部。

现在按「什么变了」拆成几个入口：

| 入口 | 触发场景 | 重画范围 |
|---|---|---|
| `refresh.all()` | 换标的、切到期日、改设置 | 全部 8 个区块 |
| `refresh.account()` | 下单、平仓、建仓、到期结算 | 持仓/风险/流水/下单面板，**期权链只同步持仓标记** |
| `refresh.chainOnly()` | 切换希腊字母列、平值范围 | 仅期权链 |
| `refresh.charts()` | 窗口尺寸变化 | 仅含 Canvas 的区块 |

关键在 `refresh.account()`：下单后期权链的**报价并没有变**，只有「哪些合约
有持仓」变了。所以不重建表格，只用 `classList.toggle` 同步标记 ——
顺带保住了滚动位置。`test/ui-refresh-test.js` 对此有断言（600 → 600）。

### 事件委托

期权链一次渲染会产生 600+ 个可点击单元格。逐个绑 `onclick` 不只是开销问题，
更容易出现「重建后忘记重绑 → 点击静默失效」这类难查的 bug。
现在在稳定的父容器上各绑一次，靠 `closest()` 找目标；
新增可点击元素只需带上约定的 `data-*` 属性。

### 改动本文件时的三条约定

1. 渲染函数只读 `S`、不改 `S`；状态变更走事件处理器，改完调 `refresh.*`
2. 不要退回全量重画 —— 新增区块挂到对应的 `refresh` 入口下
3. 反复重建的容器内，点击一律走事件委托

这套分层也是将来迁移的准备：若要换到 Preact/Vue，替换范围仅限 `app.js` 的
`render*` 部分，`S` 与 `refresh` 可直接映射成组件的 props 与状态。
